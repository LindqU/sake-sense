# 作業記録: 招待制サインアップと閲覧モード・権限制御の実装

## 実施日
2026年2月11日

## 作業概要
「閲覧は誰でも可能だが、記録・編集は本人（または招待者）のみ」という権限設計を完了させました。これに加え、複数ユーザーが利用するためのプロフィール（表示名）管理機能を構築しました。

## 実施詳細

### 1. 招待制サインアップとユーザー管理
- **招待コード機能の実装**: `app/src/components/Login.tsx` に招待コード入力を追加。環境変数 `NEXT_PUBLIC_INVITE_KEY` との照合によるバリデーションを実装。
- **プロフィール（表示名）システム**:
    - `profiles` テーブルを新設し、`auth.users` と連携してユーザーの表示名を管理。
    - サインアップ時にユーザー名を入力・保存する仕組みを構築。
- **Login UIの刷新**: indigoを基調としたグラデーションとアニメーションを取り入れ、モダンなカード型デザインに強化。

### 2. オープン閲覧（閲覧モード）の対応
- **認証状態の監視とルーティング**: `app/src/app/page.tsx` で `onAuthStateChange` を使用し、未ログイン状態でもエントリ画面と履歴画面にアクセスできるよう修正。
- **閲覧・編集の権限制御**:
    - ログインユーザーとログの `user_id` を照合し、本人以外（ゲストを含む）の場合は「閲覧モード（編集不可）」に切り替えるロジックを実装。
    - 閲覧モード中、入力フォーム、舌マップ、グラフの操作をロック（disabled化）し、保存ボタンを非表示化。
    - 未ログイン時は「ログインして記録する」ボタンを表示し、自然なログイン誘導を実現。

### 3. 歴史一覧の投稿者表示
- **投稿者名の取得**: `latest_tasting_logs` ビューを更新し、`profiles` テーブルと結合して投稿者の表示名（`author_name`）を取得。
- **UI連携**: `HistoryView.tsx` の各ログアイテムに投稿者名のバッジを表示。誰が記録したログかを一目で識別可能に。

### 4. セキュリティ（Supabase RLS）の設定
- **オープン閲覧ポリシー**: `tasting_events` に対し、誰でも取得可能な `SELECT` ポリシーを適用。
- **所有者保護ポリシー**: `INSERT`, `UPDATE`, `DELETE` は認証済みかつ `auth.uid() = user_id` の場合のみ許可する厳格なポリシーを設定（`infra/db/schema.sql`）。
- **権限付与**: `anon`（未ログイン）および `authenticated`（ログイン済）のロールに対し、必要なViewおよびテーブルへのアクセス権限を明示。
